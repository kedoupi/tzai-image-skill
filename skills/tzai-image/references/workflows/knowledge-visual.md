# Knowledge Visual

Use for requests such as "turn this research into an infographic," "explain this concept visually," or "make a process diagram." Produce 1-5 fact-grounded explanatory visuals.

## Intake

Infer audience, learning goal, core claim, supplied source facts, units, and preferred explanatory form. Ask only for material gaps: authoritative sources, definitions, data period, units, or required scope. Build a fact ledger; never infer missing metrics or causal claims.

## Plan And Approval

Choose the clearest information structure and present it before paid calls:

| Asset | Question answered | Verified facts/labels | Structure | Kind |
| --- | --- | --- | --- | --- |
| 01 | Core concept | Fact-ledger IDs | Overview | `infographic`, `diagram`, `flowchart`, or `dataviz` |
| 02-N | Supporting question | Fact-ledger IDs | Comparison, process, hierarchy, or scale | Existing planned kind |

Provide a label map that separates on-image short labels from externally typeset detail. Select exactly one explainer-composition anchor and obtain explicit plan approval.

## Two-Stage Production

1. Generate exactly one planned explainer anchor.
2. Obtain explicit anchor approval before remaining paid assets.
3. Generate approved supporting visuals using their planned existing kinds and `--ref` to the anchor. Keep the fact ledger unchanged unless the user approves a content correction.

## Delivery

Return 1-5 numbered files, a fact ledger with source references, and a label map with caption and alt text for every visual.

## Quality And Boundaries

- Verify numbers, labels, units, names, ordering, and causality. Keep dense labels, citations, and exact data in external layout.
- Regenerate a misleading or inaccurate visual only; preserve successful assets and identify any partial failure.
- This is explanatory design, not research, professional advice, scientific validation, or a substitute for source review.
