# Deck Package

Use for requests such as "create deck visuals," "make a presentation package," or "visualize this presentation outline." Produce 4-12 coordinated slide visuals, not an editable presentation file.

## Intake

Read the actual deck outline and infer audience, decision sought, presentation setting, page count, and brand system. Ask only for material gaps: outline/source facts, required pages, brand constraints, or final CTA. Separate speaker notes and final slide copy from image generation.

## Plan And Approval

Create a page-role and content plan before paid calls:

| # | Page role | One idea | Overlay copy | Kind |
| --- | --- | --- | --- | --- |
| 01 | Title | Deck promise | External title | `slide` |
| 02-N | Divider, content, metric, process, system, or product | One takeaway | External title/labels | `slide`, `infographic`, `flowchart`, `architecture`, or `ui` |

Define the shared visual system and title-safe areas. Select exactly one title-slide anchor and obtain explicit plan approval.

## Two-Stage Production

1. Generate exactly one `slide` title anchor.
2. Obtain explicit anchor approval before generating any remaining visuals.
3. Generate the planned pages with their existing kinds and `--ref` to the anchor. Maintain one visual idea per page and adapt layout to the role.

## Delivery

Return 4-12 numbered files, the page-role map, suggested overlay copy, image placement, captions, and alt text. Provide a package for deck assembly, not a PPTX.

## Quality And Boundaries

- Type final titles, dense diagrams, numbers, and citations in the presentation; verify all factual content and rendered text.
- Preserve approved pages when one fails. Regenerate only the failed page with the anchor and report partial delivery.
- This does not create presentation software, validate business claims, or guarantee accessibility or presentation effectiveness.
