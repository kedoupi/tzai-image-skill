# Pattern Library Methodology

Patterns are reusable design methods, not copied examples. A pattern converts a recurring creative problem into a small set of controllable decisions: audience, message hierarchy, composition, visual treatment, format, and acceptance checks.

## Pattern Shape

Each pattern should specify:

| Field | Question it answers |
| --- | --- |
| Problem | What communication or visual task recurs? |
| Inputs | What facts, copy, brand rules, format, or references are required? |
| Structure | What hierarchy, sequence, or layout governs the result? |
| Controls | Which kind, aspect ratio, preset, style, palette, or rendering choices apply? |
| Output | Which content and image artifacts are delivered? |
| Checks | What must be reviewed before approval? |
| Boundaries | What is deliberately not promised, such as exact text fidelity or trademark clearance? |

## Derivation Method

1. Observe several examples of the same problem and identify the shared function, not their distinctive artwork.
2. Abstract the minimum useful variables. For example, an infographic pattern may need a claim, 3-5 facts, a reading order, and a visual metaphor, rather than a long source prompt.
3. Rewrite the method in original language and fit it to tzai-image kinds and matrices.
4. Test it with different subjects. A pattern is useful only if it survives a change of topic, audience, and brand.
5. Document failure modes and the approval point. Escalate to a guided or expert workflow when the pattern cannot safely resolve a key decision.

## Pattern Families

| Family | Typical use | First-class concern |
| --- | --- | --- |
| Information hierarchy | Infographics, explainers, diagrams | Accurate content and reading order |
| Series system | Social cards, decks, article sets | Consistency across named artifacts |
| Brand expression | Icons, covers, campaign art | Distinctive direction without imitation |
| Product communication | UI concepts, product photography | Feature focus and audience context |
| Narrative sequence | Storyboards, storybooks | Beat order and continuity |

## Originality and Safety

Patterns may learn from public examples, but they must be independently written. Do not copy source images, logos, layouts as finished assets, or full prompts into this repository. Preserve only generalized methods such as "establish a single focal object, then place three supporting facts in reading order."

Avoid requests to reproduce a living artist's signature style, protected character, trade dress, or a specific third-party image. When a user provides a reference, treat it as a constraint they are responsible for having the right to use; do not imply that generation grants ownership or commercial clearance.

## Quality Review

Review a pattern output against the brief before calling it complete:

- Content: facts, labels, sequence, language, and required claims are correct.
- Composition: the focal point and reading order support the intended channel.
- System: project items share the approved palette, typography intent, and visual rules.
- Production: aspect ratio, file path, and reference use match the render plan.
- Rights: no unapproved source asset or copied prompt has entered the deliverable.
